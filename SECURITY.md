# Security

Do not report a vulnerability containing credentials, private records, personal
photos or an exploitable account boundary in a public issue.

Use the repository's **Security → Report a vulnerability** option when private
reporting is enabled. If that option is unavailable, ask a maintainer for a
private reporting channel without posting the exploit or affected account data.
No response-time commitment or paid bounty is offered here.

Include the affected revision, a minimal reproduction using disposable data,
the expected boundary and the observed result. Redact tokens, signed URLs and
project-specific identifiers. Do not test against accounts you do not control,
spend provider money, widen production access or delete another person's data.

Before publishing a fork, configure its own reporting channel and review its
Fóir permissions, signed-operation verification, dependency versions and media
access. This template's local public-tree scan supplements secret scanning and
manual review; it does not certify a deployment or its configuration.
